# Source Note: Private and Semi-Private Source Intake

This page defines a repeatable intake process for email archives, mailing lists, chat exports, private docs, and similar semi-private material.

## Intake Workflow

1. Record the source family and access level.
2. Record whether reuse permission exists, is unclear, or is explicitly denied.
3. Decide whether the material is safe for summarize-only use or should be excluded entirely.
4. Extract only practical lessons, not private identity or conversational detail.
5. Create a provenance note before any public article is drafted.

## Default Rules

- Public docs and public repos: normal summarization allowed.
- Semi-private material such as mailing lists or member forums: summarize-only by default.
- Private email, chats, or internal docs: do not publish derived content without clear permission.
- If permission status is unclear, treat the source as blocked for public article generation.

## Editorial Pattern For Allowed Private-Derived Content

- Do not quote unless permission explicitly allows quotation.
- Prefer generalized lessons over incident retellings.
- Remove names, timestamps, and identifying discussion context unless publication permission explicitly covers them.
- Keep provenance explicit in `sources/` even if the public article only references the source family generically.
